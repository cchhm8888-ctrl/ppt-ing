# Production Workflow

1. Route the request.
2. For proposal-first, run the single intake.
3. Inspect reference/template pack.
4. Run compact Pinterest research.
5. Produce the nine-module proposal and complete slide table.
6. Wait for proposal approval.
7. Ask A/B/C visual-target choice.
8. Resolve assets; generate missing conceptual assets when required.
9. For B/C, produce and approve the reference set. B uses the four-file bundle; C uses full-page references plus FigEdit boundary.
10. Validate `presentation-brief.json` and `slide-spec.json`.
11. Construct only after required assets, commitments, expected objects, and approvals are resolved.
12. Render every page from the working PPTX.
13. Compare to references and run design, editability, content, motion, and structural QA.
14. Fix native objects/spec, re-render, and deliver a new file unless overwrite was explicitly requested.

## Build checkpoints

- Page-role grammar complete.
- Template pack and variants assigned.
- Typography slots and effects assigned.
- Shape/mask recipes and crop/focal data assigned.
- Every commitment references expected object IDs.
- Route B bundle or Route C extraction evidence complete.
- No required asset unresolved.

## Direct mode

Infer all planning internally and default to Route B. Do not expose intake or proposal; still compile the same page-role, template, typography, shape, asset, motion, and reference contracts.

## Lightweight route

Preserve the existing master, content, visuals, and motion outside the requested scope. Run only proportional validation.
