# Intake, Research, Proposal, Approval

## Single intake

Ask the eight items in one visible block. Prefill known facts from supplied files. The user may answer `全部推荐`. Do not repeat the questionnaire. Missing preferences use defaults; missing facts may block production.

The optional attachment line accepts a template/reference pack without becoming a ninth question. Record each item as `user-template`, `user-style-reference`, `licensed-library`, or `pinterest-signal`, plus path/URL, permission, and intended use.

## Research order

`intake → reference/template analysis → 3–5 Pinterest signals → proposal`

Template analysis extracts ratio, masters/layouts, theme colors, fonts, editable components, chart patterns, image windows, navigation, and brand constraints. Pinterest research records transferable signals and provenance only.

## Proposal output

The proposal has nine modules and a complete slide table. It must name:

- primary and secondary template packs;
- page-role grammar and section map;
- 5–7 families and, for 15+ slides, at least 8 variants;
- six typography roles, 4+ named presets when 15+ slides, and 3 purposeful treatments;
- native component, chart, shape, mask, and motion recipes;
- per-slide design commitments and expected objects.

The slide table fields are:

`page / page_role / section_id / narrative_job / title / core_copy / layout_family / layout_variant_id / primary_visual / shape_recipe / typography_preset / motion_recipe / source`

## Approval state

- `pending`: proposal shown; no production.
- `approved`: user explicitly confirms.
- `revision_requested`: update the complete proposal and increment version; do not repeat intake.
- `bypassed`: direct mode only.

After proposal approval, ask only the A/B/C visual-target choice. Design-preview, reference-set, and FigEdit extraction confirmations are stage approvals, not preference intake.
